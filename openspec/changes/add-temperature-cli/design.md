# Design

## Context

仓库现有 `todo` 是单文件 Python 脚本，仅用标准库，命令通过 `argparse` 子命令分发，错误统一写 stderr 并以非零状态码退出；测试用 `unittest` 加子进程调用。`temp` 是一个完全无状态、无 IO 的新命令，不需要数据文件，也不应影响 `todo`。

需求与行为契约见 `specs/temperature-conversion/spec.md`；动机见 `proposal.md`。

## Goals / Non-Goals

**Goals:**

- 用最少的代码实现可测试、可脚本化的双向温度换算。
- 与现有仓库的 Python 版本、错误输出和测试习惯保持一致。
- 把数值格式化与物理边界校验做成明确的、可单测的行为。

**Non-Goals:**

- 不引入第三方依赖、打包配置或安装器。
- 不扩展开尔文、兰金等其他单位。
- 不支持交互式 REPL、标准输入或批量文件转换。
- 不做历史记录或数据持久化。

## Decisions

### 独立脚本而非 `todo` 子命令

新增根目录可执行脚本 `temp`，与 `todo` 平级，通过软链接加入 `PATH`。

- 理由：两个领域正交，独立脚本可以使用最简洁的帮助文本与 `prog` 名称，也不会让 `todo` 的解析器承担无关参数。
- 备选：作为 `todo c2f` 子命令。实现更省，但把无关领域耦合成一个命令，帮助信息也会混杂。

### 显式方向子命令

接口固定为 `temp c2f <值>` 与 `temp f2c <值>`。

- 理由：方向与单位在命令中显式出现，不存在“这个数字是摄氏还是华氏”的猜测；也符合现有 `todo` 的子命令风格。
- 备选：`--from/--to` 选项更易扩展到其他单位，但每次调用都要写两个选项；单位后缀 `100c` 最短，但解析规则隐晦。

### 使用 `float` 而非 `Decimal`

转换与格式化都基于 Python `float`。

- 理由：规格只要求显示层面的 4 位小数；`float` 足以覆盖该精度，代码和标准库行为都更简单。
- 备选：`Decimal` 能避免二进制浮点误差，但对一个展示型换算工具属于过度设计，并会引入字符串量化规则。
- 已知代价：显示舍入后的结果再次代入不会严格可逆，这是展示精度的固有结果。

### 格式化：固定小数位后去尾零

结果用 `f"{value:.{precision}f}"` 生成，再依次去掉末尾的 `0` 与 `.`；若结果为 `-0`，归一化为 `0`；单位只用 ASCII 的 `C` / `F`。

- 理由：行为可预测，整数结果干净，且符合仓库“纯 ASCII、便于管道”的约定。
- 备选：有效数字或科学计数法更适合极小/极大值，但会让日常输出的形态不稳定，当前不做。
- `--precision` 限制为 0–10，避免生成无意义的超长输出。

### 校验分三层，统一映射到退出码

1. 参数解析：子命令、数值参数、`--precision` 的整数与范围，由 `argparse` 处理，失败退出码 2。
2. 输入校验：`float()` 失败、非有限值（`nan` / `inf`）、低于绝对零度，抛业务异常，退出码 1。
3. 结果校验：换算结果非有限（如 `c2f 1e308` 溢出），同样按业务异常处理，退出码 1。

业务异常由 `main()` 统一捕获，输出 `temp: error: ...` 到 stderr；stdout 不产生部分结果。

### 测试使用子进程，不引入测试框架

新增 `tests/test_temp.py`，复用 `unittest`，通过子进程运行脚本并断言 stdout、stderr 与退出码。

- 理由：与现有测试风格一致，能真实覆盖参数解析和进程退出码。
- 测试不依赖 `XDG_DATA_HOME` 或任何临时数据目录。
- 必须覆盖负数位置参数 `temp c2f -40`：当前解析器没有短选项，`argparse` 会把它当作位置参数；若未来加入短选项，需要保持这一行为不回归。

## Risks / Trade-offs

- [默认按小数位而非有效数字舍入，极小值会被显示为 `0`] → 已在规格中接受；若将来需要科学计算，再引入有效数字选项，不改变现有默认。
- [显示精度导致往返换算不完全可逆] → 属于展示型工具的预期行为；规格只承诺单次换算结果。
- [物理边界校验拒绝低于绝对零度的数学输入] → 规格明确要求报错；如出现真实的假设性换算需求，可后续增加显式覆盖选项。
- [`argparse` 对负数位置参数的处理依赖当前没有“像负数”的选项] → 用 `temp c2f -40` 的测试锁定行为；新增选项时避免使用 `-数字` 形式的短选项。
- [浮点格式化的舍入边界（如 `.5` 的银行家舍入）] → 测试使用不落在二义边界上的样例，避免把具体舍入模式写死成契约。
